SCBKR Core Schema

  • S · Subject主體 / 事件核心對象
  • C · Cause原因 / 背景脈絡
  • B · Boundary邊界 / 限制條件
  • K · Key Evidence關鍵證據 / 來源鏈
  • R · Responsibility責任歸屬 / 追溯節點

Open indexing layer only · 僅開放索引層，不包含封閉治理判斷核心

About SCBKR / 關於 SCBKR

What it is / 是什麼

SCBKR uses five fields—Subject, Cause, Boundary, Key Evidence, Responsibility—to describe each memory item in a consistent, reviewable way.

SCBKR 用五個欄位描述每筆記憶：Subject、Cause、Boundary、Key Evidence、Responsibility， 讓資料更一致、可追溯、可檢查。

Why not RAG-only / 為何不只做 RAG

Traditional RAG finds related text chunks. SCBKR adds structure around why the memory exists, what boundaries apply, what evidence supports it, and who is responsible.

所以這個專案重點是「可維護的記憶索引層」，不是最終判斷系統；你可以在其上接自己的模型與規則。

Quick Usage Guide / 快速使用指南

Step 1 · 進入 starter-package

下載 Repo ZIP 解壓後，真正要使用記憶索引的目錄是 main-root/starter-package/memory-index/。

Use this folder first. The frontend files are for website display, not indexing execution.

Step 2 · 放入你的記憶資料

把你的檔案放進以下三個子目錄：

memory-index/json/
memory-index/drive-import/
memory-index/local-private/

這樣可用同一套 SCBKR 結構管理不同來源記憶，降低遺忘與漂移。

Step 3 · 產生索引並檢查結果

cd main-root/starter-package
python3 tools/auto_index.py \
  --source ./memory-index \
  --output ./memory-index/index.scbkr.generated.json

先確認 JSON 已成功產生，再接自己的查詢流程與模型。 Start by verifying the JSON output, then integrate your own query flow and model stack.
